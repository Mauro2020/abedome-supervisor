# ABEDOME controlled update feed

## Status

**Foundation only — not active in released images.**

The Proxmox validation image continues to use the upstream Home Assistant release
feed. It must not be used to test a product update path.

## Why this exists

Home Assistant Supervisor retrieves one version manifest that determines the
available Home Assistant OS, Core, Supervisor, and supporting-service versions,
as well as the OTA URL. A controlled ABEDOME release path therefore needs an
ABEDOME-owned manifest rather than a partial OS-only override.

This fork accepts the `SUPERVISOR_VERSION_URL` environment variable as a URL
template. The template must include `{channel}`, for example:

```text
https://updates.example.invalid/{channel}.json
```

When the variable is absent, upstream behavior remains unchanged:

```text
https://version.home-assistant.io/{channel}.json
```

## Activation gate

The variable must not be enabled in ABEDOME OS until all of these exist:

1. An immutable ABEDOME version manifest, published only from an approved release.
2. Signed ABEDOME OS artifacts at the manifest's declared OTA URLs.
3. A production RAUC key held only in repository secrets; never reuse the public
   test key generated by a development build.
4. Pinned, approved container images for every component declared by the manifest.
5. A successful end-to-end update and rollback test in Proxmox.

The feed must never reference a moving GitHub branch or an auto-merged upstream
change. Every promoted version requires an ABEDOME pull request and explicit
approval.
